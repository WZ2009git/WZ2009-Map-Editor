# Map height, outskirts and shared water

In the Map workshop, **Map height and shared water** uses persistent map-instance
IDs. Choose a map from the list, or click any of its parts and choose **Use map
from selected part**. **Select whole map - G / R** selects its parent so all
geometry, props, previews and loaded outskirts move together. Unloaded detail
libraries remain map-local and use the new placement on their next load.

**Target root Z** is an absolute world height; **Apply map height** moves the
whole map to it. **Raise map / Lower map** use **Height step**. **Set root to
water + offset** aligns the map's placement pivot, not a detected ground or
shoreline. Choose the offset visually. Existing XY placement, rotation and scale
are preserved. Blender world units are used; no native-source-to-metre physical
calibration is inferred.

**Water Z** and **Water width / length** reuse the existing terrain sea settings.
**Create / update water reference** applies them to one stable sea record and a
cheap flat surface. **Fit water around current maps** fits its extent around the
overview bounds. Toggle **Show water preview** and apply to show/hide it. The
surface cannot intercept map selection and is excluded from renders. It is an
editor reference, not collision, buoyancy, a terrain carve or an engine ocean.
Changing water never changes map heights automatically. Existing native water
objects, including the user's deletions, are not regenerated by this action.

**Load outskirts as parts** prepares disconnected terrain and native prop
placements once, retaining shared prop mesh data. **Save + hide outskirts**
writes a new version, removes only that layer from the scene and releases unused
data. Loading again uses the saved version without repeating separation.
Physically connected surfaces may remain one object. Existing core edits are
kept separate. **Edit selected mesh faces** makes shared prop geometry unique
for the chosen placement.

Save the Blender composition after saving detail libraries, so its updated
library references and map placement remain together. The implementation task
starts from a separate live-scene checkpoint and saves its result to a new file;
the user's prior workspace remains unchanged.

## Ultra-Water evaluation

Reviewed source: [Humpalumps/Ultra-Water](https://github.com/Humpalumps/Ultra-Water),
HEAD `ce9248fa20afbdf63fd4c11709f68d7368aca0a0` on October 31, 2026.
Its [MIT license](https://github.com/Humpalumps/Ultra-Water/blob/ce9248fa20afbdf63fd4c11709f68d7368aca0a0/LICENSE)
requires preservation of its copyright and license when distributing copies or
substantial portions. No upstream code/assets are copied or downloaded by normal
editor operation.

It is JavaScript/Three.js/WebGL2. OceanSim uses GPU render targets and GLSL FFT
passes; OceanSurface and other passes implement ocean shading, shore effects,
underwater appearance and floating-object interaction. These do not execute as
Blender material nodes or Python add-on code. A native Blender implementation
would require adapting simulation, GPU resources, shader interfaces, depth and
reflection passes, shoreline data and time sampling. The current flat reference
does not reproduce its simulation or appearance.

The engine can later reuse the authored water level/extent and map placements,
but actual integration requires an explicit adapter to the engine's rendering,
physics, world scale and coordinate conventions (Blender is Z-up; upstream
ocean height is Y). Bathymetry, shoreline generation, floating-body forces and
network/determinism behaviour need their own validation. No existing runtime
importer or shared schema is changed here. Rust gameplay/renderer integration
remains outside this editor task; no Claude handoff is sent automatically.
